# Entity Relationship Diagram

## Built schema (pgAdmin 4 ERD tool)

Generated by pgAdmin 4's ERD tool from the `marketplace` schema in the course Supabase database. It shows all 13 tables, their columns, keys and foreign-key relationships.

## Same model as text (renders on GitHub)

Crow's-foot notation: `||` = exactly one, `o|` = zero or one, `o{` = zero or many, `|{` = one or many.

```mermaid
erDiagram
    CATEGORY ||--o{ PRODUCT : "classifies"
    SELLER   ||--o{ PRODUCT : "lists"
    PRODUCT  ||--|{ PRODUCT_VARIANT : "is sold as"
    PRODUCT  ||--o{ REVIEW : "receives"
    CUSTOMER ||--o{ REVIEW : "writes"
    CUSTOMER ||--o{ ADDRESS : "saves"
    CUSTOMER ||--o| APP_USER : "logs in as"
    ADDRESS  ||--o{ ORDER_HEADER : "ships"
    ORDER_HEADER    ||--|{ ORDER_ITEM : "contains"
    PRODUCT_VARIANT ||--o{ ORDER_ITEM : "is bought in"
    ORDER_HEADER    ||--o{ PAYMENT : "is paid by"
    SELLER          ||--o{ SELLER_PAYOUT : "is paid"
    ORDER_HEADER    ||--o{ SELLER_PAYOUT : "pays out"

    CATEGORY {
        int category_id PK
        varchar category_name UK
    }
    SELLER {
        int seller_id PK
        varchar business_name
        varchar contact_email UK
        varchar phone
        varchar approval_status
    }
    CUSTOMER {
        int customer_id PK
        varchar first_name
        varchar last_name
        varchar email UK
        varchar phone
    }
    ADDRESS {
        int address_id PK
        int customer_id FK
        varchar label
        varchar street
        varchar city
        char state
        varchar postal_code
        boolean is_active
    }
    PRODUCT {
        int product_id PK
        int seller_id FK
        int category_id FK
        varchar product_name
        text description
        numeric base_price
    }
    PRODUCT_VARIANT {
        int product_id PK,FK
        varchar sku PK
        varchar size
        varchar color
        int stock_quantity
        numeric price_override
        int reorder_level
    }
    ORDER_HEADER {
        int order_id PK
        int address_id FK
        timestamptz order_date
        varchar status
        numeric total_amount
    }
    ORDER_ITEM {
        int order_item_id PK
        int order_id FK
        int product_id FK
        varchar sku FK
        int quantity
        numeric unit_price
    }
    PAYMENT {
        int payment_id PK
        int order_id FK
        numeric amount
        timestamptz payment_date
        varchar payment_method
        varchar status
    }
    REVIEW {
        int review_id PK
        int customer_id FK
        int product_id FK
        smallint rating
        text comment
        timestamptz review_date
    }
    SELLER_PAYOUT {
        int payout_id PK
        int seller_id FK
        int order_id FK
        numeric gross_amount
        numeric commission
        numeric net_amount
        timestamptz paid_at
    }
    APP_USER {
        text role_name PK
        int customer_id FK,UK
    }
    VARIANT_AUDIT {
        bigint audit_id PK
        int product_id
        varchar sku
        int old_stock_quantity
        int new_stock_quantity
        numeric old_price_override
        numeric new_price_override
        text changed_by
        timestamptz changed_at
    }
```

`VARIANT_AUDIT` has no relationship lines on purpose: it is an audit log filled by the `trg_variant_audit` trigger and has no foreign keys, so its history survives if a variant is later deleted.

Column-level detail (types, nullability, defaults, CHECK rules and descriptions) is in [data-dictionary.md](data-dictionary.md).
